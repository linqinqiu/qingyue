# PROPOSAL-020 阅读界面重做（参照 legado-with-MD3）

用户 2026-10-13：「reader 界面重做，借助 GitHub 仓库原有的」，并指定参照 **HapeLee/legado-with-MD3**
（Material Design 3 重绘版 Legado）、范围为**全面重做**。本文定重做的范围、改法、顺序与验收 —— 确认后按此实施。

## 一、参照方研究结论（HapeLee/legado-with-MD3）

GPL-3.0，Android Jetpack Compose，6461 star。**只借交互与信息架构、视觉风格，代码一行不进**
（它是 Kotlin/Compose，我们是 Web React，且 GPL 不等价问题同 PROPOSAL-019）。其阅读界面（源码
`ui/book/read/` + `ui/widget/components/reader/`，帮助文档 `readMenuHelp.md`）要点：

- **主菜单三块**
  - **顶栏**：章节名（点击编辑书源）、章节 URL、一排**可配置**动作图标（最多 6 个，长按图标显示文字）
  - **左中**：亮度竖条（顶端「跟随系统亮度」开关）
  - **底栏**：4 个圆钮（全文搜索 / 自动翻页 / 替换净化 / 切换夜间模式）；「上一章 | **页码进度条** | 下一章」；
    再一行「目录 / 朗读 / 界面 / 设置」
- **「界面」**= 全部排版设置（底部弹层：白天/夜间、共用布局、背景网格、长按背景进文字色与背景色）
- **「设置」**= 屏幕方向/超时、隐藏状态栏/导航栏、文字两端对齐、音量键翻页、点击区域、自定义翻页按键
- **视觉**：Material 3 —— 菜单背景**顶/底渐隐**（不透明→透明）、圆角方块按钮、可选**玻璃（Backdrop）**质感；
  主题用 Monet 动态取色
- **按钮是共享注册表**：顶栏、浮动图标行、底栏三处共用一份动作定义（图标+文案+点击+适用条件），
  各按配置（顺序+开关）取用 —— 与本仓 `web/src/reader/readerMenu.ts` 已是同一思路

## 二、现状与问题

现有阅读器（`web/src/reader/`，0.7.0）：沉浸式（顶/底栏默认隐藏、点中央唤出）；顶栏
「返回/目录 | 书名 | 切换书源/阅读设置/全屏/朗读」；设置是**三标签页**面板（排版/颜色/行为）；
另有目录抽屉、TTS 悬浮条、笔记/划线、简繁转换、阅读记录、7 皮肤+自定义、翻页动画（滑动/淡入/覆盖）、
滚动与分页两模式、点击分区、Ctrl+滚轮字号。问题：

1. **信息架构与参照脱节**：没有底栏，翻页/进度靠隐式手势与顶栏按钮，与 MD3「顶栏管信息、底栏管导航与
   常用动作」的布局不同；设置挤在一个三标签面板里，找不到的东西多。
2. **观感不是 MD3**：菜单无顶/底渐隐、无圆角方块/玻璃质感，与参照的现代感差一截。
3. **按钮来源分散**：顶栏按钮在 `ReaderHeader.tsx` 写死，与 `readerMenu.ts` 的注册表只有一半对齐，
   缺「浮动图标行」这一处消费方。

## 三、改动（分阶段，每阶段可独立验收、可回退）

**总原则**：新旧两套 UI 用 `localStorage: reader-ui-v2` + URL `?ui=md3` 开关并存，默认**保持旧界面**，
逐阶段推进；每阶段末跑全量门禁。

### P0 门禁契约层（前置，零风险）

- **目标**：让后续改 UI 不被门禁卡死。现在大量浏览器门禁靠 `.reader-*` class 锚在阅读器 DOM 上。
- **改法**：给**所有被门禁断言**的阅读器元素加 `data-testid`（`reader-header` / `reader-chapter-title` /
  `reader-settings-*` 等），门禁从 class 选择器改到 `[data-testid=...]`。新旧界面都实现同一套 testid。
- **验收**：`grep tools/verify` 出全部 reader 锚点 → 逐一迁到 testid → 全量门禁仍绿（此时 UI 未动）。
- **回退**：纯增量，删掉即可。

### P1 MD3 外壳与按钮注册表

- **目标**：新顶栏（MD3 圆角/顶渐隐）+ 新底栏（圆角方块按钮组 + 上一章/下一章），按钮统一来自注册表。
- **改法**：`readerMenu.ts` 扩成 `ActionRegistry`（`{id, icon, label, onClick, applicable}`），
  顶栏 / 底栏 / 浮动图标行三处共用；底栏布局按 MD3 分两行（圆钮行 + 目录/朗读/界面/设置）。**此阶段不含
  进度条**，上一章/下一章沿用现有跳章逻辑。
- **验收**：开关切到 md3 外壳时按钮齐、点击行为与旧版一致；`ui-shell-check` 在新旧两态各跑一次。
- **回退**：关开关。

### P2 底栏页码进度条（★ 最高风险）

- **目标**：底栏「上一章 | 进度条 | 下一章」，进度条可拖拽跳页/跳位置。
- **改法**：滚动模式进度 = `scrollTop / scrollHeight` 百分比（拖拽用 `requestAnimationFrame` 节流，
  松手再 `scrollTo`）；分页模式进度 = 现有分页网格的页码。**只调 `readerFlow.ts` / `pageTurn.ts` 的对外
  接口，不重写分页算法**。
- **风险**：唯一动到阅读引擎的阶段 —— Web 无真实页码，滚动/分页两套进度计算、虚拟分页高度估算、拖拽
  性能都可能出 bug，直接导致「读不了」。故单列一阶段、单列回退。
- **验收**：新增门禁「拖进度条到 50% → 正文落点与直接跳该位置一致（滚动）/ 页码一致（分页）」；
  `paginate-flow-check` / `reader-flow-check` 不回归。
- **回退**：进度条单独摘掉，底栏退回上一章/下一章。

### P3「界面」底部弹层

- **目标**：把现有**三标签面板**（排版/颜色/行为）整体搬进 MD3 底部弹层，并合并皮肤网格与翻页动画。
- **改法**：新建 `ReaderSheet`（底部弹层容器，复用给 P4）；排版+颜色+皮肤+翻页动画+滚动/分页 → 「界面」；
  三标签结构保留（本仓已适配，不推倒）。
- **验收**：门禁改锚 testid 后全绿；三标签面板从顶栏彻底下线。
- **回退**：开关切回旧面板。

### P4「设置」底部弹层

- **目标**：新建「设置」弹层，收纳 `BehaviorTab` 里的行为项 + 全屏/沉浸、两端对齐、点击分区、键盘翻页等。
- **改法**：复用 `ReaderSheet`；行为类从「界面」拆到「设置」（对齐 MD3 的「界面=排版、设置=其它」）。
- **验收**：功能一一对应、可持久化；`ui-shell-check` 不回归。
- **回退**：开关切回旧面板。

### P5 视觉抛光（低风险，纯 CSS/主题）

- **目标**：顶/底渐隐、`backdrop-filter` 玻璃增强（`@supports` 检测，默认关）、MD3 tonal palette。
- **改法**：玻璃走特性检测降级（不支持就是半透明纯色）；**Monet 动态取色舍弃全量、借思想** ——
  把现有 7 套皮肤 + 自定义皮肤映射为 MD3 tonal palette（`--md-sys-color-*` CSS 变量），不做实时取色。
- **验收**：Lighthouse 性能不掉 10 分以上；不支持玻璃的浏览器观感不破。
- **回退**：CSS 开关。

## 四、顺序

**P0（门禁解耦，必须先做，否则后面每步都被门禁卡）→ P1（外壳）→ P2（进度条，高风险先啃）→
P3（界面弹层）→ P4（设置弹层）→ P5（抛光）**。

## 五、红线

- 上游代码一行不进（MD3 是 GPL-3.0 的 Kotlin/Compose，只借交互与视觉）。
- **不新增功能**：本次是「重做界面」，现有功能只换摆放/入口，不增不减（除非用户另行要求）。
- 门禁锚点若因结构变化而移动，**同步改门禁**，不许绕过；先做 P0 把锚点从 class 迁到 `data-testid`。
- 每完成一阶段 → `CHANGELOG` 顶部补一句、跑 `version-check`；版本号按「小更新计数」递增。
- 全程 `reader-ui-v2` 开关可回退，默认保持旧界面直到新界面验收通过。
