## 0. 为什么是这两条（本机实测，不是印象）

### 0.1 逗号段翻页写法：这类栏目在发现页**今天就是打不开的**

复现：`node E:\legado\_probe\qingyue-ref\corpus-paging-shape2.mjs`（只读语料）

| 项 | 实测值 |
|---|---|
| 语料 | 5,574 份书源：没配 `exploreUrl` 2,728 · **JS 型 336** · **静态写法 2,510** |

第一版统计（`corpus-paging-shape.mjs`）报的是 2,698，**被污染了**：JS 型 `exploreUrl` 里的
`for(var i=0;i<bangdans.length;i++)` 长得像"带逗号的尖括号段"，被当成栏目地址数了进去。
上面这张表是加了"整段含 `@js:` / `js:` / `<js>` 就跳过 + 栏目地址必须长得像网址"两道闸门后重量的。
**记在这儿，是为了下次不许再拿第一遍的结论进方案。**

症状是当场演出来的（`node E:\legado\_probe\qingyue-ref\paging-symptom-probe.mjs`，喂 1299 隔离实例）：

```
样本源：饭饭小说  http://www.ffxs8.com
栏目原文：都市言情::/dsyq/<,index_{{page}}.html>
服务端解析出的栏目：「都市言情」 url=/dsyq/<,index_{{page}}.html>
  第 1 页：HTTP 502 · {"code":"explore_failed","message":"URL 格式无效或包含未解析变量: /dsyq/<,index_1.html>"}
  第 2 页：HTTP 502 · {"code":"explore_failed","message":"URL 格式无效或包含未解析变量: /dsyq/<,index_2.html>"}
```

**注意是第 1 页就 502**，不是"翻不动第二页"。`renderUrl`（`server/src/main/kotlin/io/legado/server/rules/RuleRunner.kt`）
只替 `<key>` 这一个尖括号形态，`{{page}}` 替完之后剩下的 `<,index_1.html>` 原样留在网址里，
过不了 URI 解析。所以这种源在发现页是**整栏全死**，用户看到的是「这一栏取不到」。

### 0.2 上游的语义（读 `AnalyzeUrl.kt` 的 page 段，只取规则不取代码）

- 时机：在 `{{…}}` 表达式求值**之后**再做（所以 `<,index_{{page}}.html>` 里的 `{{page}}` 先变成数字）。
- 取值：`<(.*?)>` 非贪婪逐段匹配；段内按 `,` 切成 `pages`；
  **第 N 页取 `pages[N-1]`，超出长度取最后一条**（上游注释写明 `pages[size-1]` 等同 `pages.last()`）；
  两端按"≤ 空格的字符"裁掉；整段（含尖括号）替换成取到的那一条。
- 只在**请求带了页码**时才做这件事。
- 于是样本源：第 1 页 → `/dsyq/`（第一段是空串），第 2 页 → `/dsyq/index_2.html`。

## 1. P0.1 让 `<a,b,c>` 真的能翻页

- **落点**：`renderUrl` 里补这一段语义（顺序：字面量 → `{{…}}` 求值 → `<…>` 选段 → 交 URI）。
  不动 `search()` / `explore()` 的 JS 分支，不动书源数据。
- **判据**（`server/src/test/kotlin/`，形状照 `MediaUrlSniffTest.kt` 那份假上游 fetcher）：
  ① `<,index_{{page}}.html>` 第 1 页得 `/dsyq/`、第 2 页得 `/dsyq/index_2.html`（**从 502 变 200** 这条要有用例）；
  ② 超出段数取最后一条（`<a,b>` 第 5 页 = `b`）；③ 没有页码时**不动**尖括号；
  ④ 反向对照：`<key>` 与 `{{page}}` 的既有行为不许被改坏；
  ⑤ 端到端一条：把 0.1 那个真实栏目原文喂进去，断言最终网址里**不再出现尖括号**。
- **界面**：发现页那一栏从「取不到」变成能出条目，不需要新控件。

## 2. P0.2 图片要能"重取"这一张

现状（三层都量过，缺一层都会白做）：

| 层 | 现状 | 出处 |
|---|---|---|
| 盘上 | `CoverCache` 按 `sha256(url)` 平铺一份，**命中就回，永不过期、没有作废入口**（全 `Routes.kt` 无 refresh/force） | `server/src/main/kotlin/io/legado/server/cache/CoverCache.kt` |
| HTTP | `/api/book/image` 与 `/api/covers/*` 都回 `max-age=7 天` | `server/src/main/kotlin/io/legado/server/http/Routes.kt` |
| Service Worker | `legado-covers` 命中 `/api/covers(/\|$)`，`StaleWhileRevalidate` + 30 天 / 300 条；**正文配图 `/api/book/image` 不在这条规则里** | `web/vite.config.ts` |

所以：**站点用同一个 URL 换了图**（改了封面、把占位图换成真图、图被重新上传），
青阅会一直显示错的那张，界面上没有任何动作能救。上游这一簇（`5cf367c` 等）解决的是同一件事。

- **设计形状**（不是实现）：作废 = 删盘上那个 key **并且**让浏览器那份副本绕开。
  只删盘不够 —— SWR 会先给旧的、后台再取（要第二次加载才对），而 7 天 `max-age` 让浏览器**根本不再来问**。
  所以取图地址要带一个"版本位"（`&v=<每本书/每张图的代次>`），重取时只换代次，URL 一变，
  HTTP 缓存与 SW 那份自然落空。
- **入口放哪儿**：阅读器的「图片」出错时那一行，与书源详情里的封面预览各一颗「重新取这张」；
  不做批量清缓存（那是另一件事，且容易变成"一键把事情搞坏"）。
- **判据**：① 换代次后请求的 URL 与上一次不同；② 服务端删 key 后同一 URL 会重新落盘；
  ③ 反向对照：没点重取时**不许**每次都绕缓存（否则每张图都双份请求）。

## 3. P1 「这一栏能不能翻页」要看得出来，不是试出来

现在界面永远挂一颗「下一页」，靠"发第二页、按 bookUrl 去重、空或全重就判到底"事后发现
（`web/src/pages/ExplorePage.tsx`）。上游 `8a9a5c0` 给的是**不执行书源 JS 的静态判定**，
判据表（认它支持翻页）：

| 认 | 不认 |
|---|---|
| `{{…}}` 里出现**自由变量** `page`（`{{page}}`、`{{ page }}`、`{{(page-1)*20}}`） | `?page=1` 字面量 |
| `<js>` / `@js:` 脚本里出现自由变量 `page`（含模板串 `?page=${page}`） | `{{'page'}}`、注释里的 `page`、`'https://x/page'` 字符串 |
| 剩下的 `<…>` 段里**带逗号**（`<1,2,3>`） | `{{book.page}}`、`{{({page:1}).page}}` 属性访问 |
| | `{{(function(page){…})(1)}}`、`var page = 1; … + page` 被遮蔽的 |

实现形状：用 Rhino 的 **Parser/AST** 判，不 eval（上游专门有一条"不许执行书源代码"的用例，
喂 `@js: throw new Error('must not execute'); page` 必须照样返回 true）；变量要"没有定义作用域"才算自由。
**青阅侧的收益要算清楚再动**：0.1 落地后带逗号的 2,644 条本来就支持翻页了，
这一条真正服务的是那 **4,368 条不含任何翻页写法的栏目** —— 让它们不再白点一次。
