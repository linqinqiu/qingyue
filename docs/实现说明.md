# legado-server 实现说明

本文回答四件事：**怎么做出来的、依靠什么、目录长什么样、能做到什么程度**。
所有数字都是本机（`.`）实测出来的，不是估的；口径见 §7。

- 位置：`.`
- 运行：`http://127.0.0.1:8080`（只绑回环，无登录墙）
- 技术栈：Ktor 3.4.3 + Kotlin JVM 17 + SQLite / React 19 + TypeScript + Vite（PWA）
- 规模：服务端 22 个 `.kt` 共 **9,379 行** + 前端 30 个 `.ts/.tsx` 共 **12,266 行** + `styles.css` **4,009 行**
- 上游代码基准：`LegadoTeam/legado`（规则文法与实体字段以它为准）

---

## 1. 目标与边界

把 Android 上的「开源阅读 / Legado 3」搬到本机浏览器里，作为**自用阅读网关**，同时保持与阅读 App 的书源与备份互通：

| 硬约束 | 落地方式 |
| --- | --- |
| 不引入任何 Android 组件 | `server/` 只用 JVM 标准库；`WebView` → 自研反向代理 `WebViewProxy.kt`；`Room` → JDBC + SQLite；`OkHttp` → `java.net.http.HttpClient` |
| 服务端无头 | 规则解析、沙箱执行、缓存、订阅、鉴权、持久化全在服务端进程内，前端只做展示与交互 |
| 书源生态直接复用 | 书源 JSON 字段名、规则 DSL、净化规则、Legado 备份包格式全部照上游，导入即用 |
| 界面是「阅读」不是「像阅读」 | 一级导航 = 书库/书架/发现/书源/订阅/规则/文件；阅读器顶栏只留 目录·换源·设置·朗读 |
| 只给自己用，不公网 | 只监听 `127.0.0.1`；服务不设身份，改绑非回环等于把库交给整个局域网（§8） |

第一代（自创界面 + 私有协议）没有历史包袱问题，但**发现页、分组语义、WebDAV 鉴权**三处是照自己的理解写的，后来都被上游语义纠正过 —— 见 §6「有意差异」。

### 2.1 上游依据（核对语义用，代码不搬）

### 2.2 数据依据

- **用户手机导出的阅读备份**（7,441 书源 / 254 净化 / 书架 / 阅读进度）—— 经清洗后入库 **4,876 书源**（剔除 92 个被上个项目污染成 `...com已整理` 的 URL）。它同时是：实体字段真值表、导入验收样本、**规则方言普查语料**。属私人数据：不入库、不打印内容、自检脚本绝不写它（`selfcheck.mjs` 有一条断言专门守这个）。

### 2.3 同级实现交叉核对

同机的一个零依赖 Node 版阅读器（路径按各自机器而定）与本项目**运行时互不依赖**，只作两件事的对照：① 规则方言清单与优先级（它的普查口径）；② 界面清单与交互形态（三栏工作台、阅读器页眉页脚信息位、划词菜单）。

## 3. 怎么制作的

自底向上，每层要有可执行证据才进下一层：

1. **取值内核**：Jsoup CSS（含 `id.` `class.` `tag.` `text.` `children` 简写与 `@属性` 取值）+ JsonPath（`$.` `[]` `..` `[?()]`）+ 结果方法 `@text/@textNodes/@ownText/@html`。
2. **规则文法**：按 `RuleAnalyzer` 的切分顺序补 `\|\|` → `&&` → `{{}}` → `##正则##替换` → 裸键 → `<js></js>` → `文字@js:` → `@put/@get`。**每补一条都先数语料里有多少行在用**（见 §6 的行数），按体量排优先级，不凭感觉。
3. **AnalyzeUrl**：`,{options}` 严格 JSON → 后扩到 JS 对象字面量；`{{key}}/{{page}}/{{source.*}}` + 剩余 `{{}}` 当 JS 表达式求值；`<1,3,5>` 取页尚未实现（§6）。
4. **沙箱**：Rhino + `ClassShutter` 禁全部 Java 反射；`java.*` / `cookie.*` / `source.*` / `book.*` / `chapter.*` 桥；`jsLib` 对所有规则可见；`JSON.parse` 兼容"已解析对象"（否则书源里的 `result` 属性访问与 `JSON.parse(result)` 只能活一个）。
5. **书源流程**：搜索 → 详情 → 目录 → 正文 → 净化，含 Cookie 按跳归档、重定向逐跳 SSRF 复验、2 MiB 解压后上限。
6. **数据层**：SQLite WAL + 读写分离；一表一实体类；`book_toc_cache`/`book_content_cache` 以 `(source_id, book_url, chapter_url)` 为键，离线与在线共用同一条读路径。
7. **界面**：书库 → 书架 → 阅读器 → 书源 → 发现 → 订阅 → 规则 → 文件，逐屏真浏览器截图核对（§7）。
8. **验收方法**（真正改变结论的四件事）：
   - **普查**：把 4,876 个源的全部规则字段按方言分桶计数，先修体量大的（`{{模板}}` 50,211 行、结果方法 46,694、`&&` 4,375、`@get/@put` 2,344、`文字@js:` 1,452…）。
   - **定向探针**：每种方言配一个"必定匹配"的样本判对错，落成一个 `@Test`（`RuleRunnerTest` 现有 22 条）。
   - **A/B 同一样本**：改引擎前后跑同一批真实源的全链路，看可用数变化，而不是看感觉。
   - **回归比"失败集合"不比数量**：本机 `:server:test` 长期固定 53 个失败（Windows 删不掉被占用的 SQLite，测试从不调 `database.close()`），唯一可信的判据是与干净基线逐条 diff。

## 5. 功能清单

**界面（7 个一级 + 阅读器）**
书库（多源流式搜索、**搜索范围三分法：全部书源 / 按分组 / 指定书源**、按源分组、结果排序、历史）· 书架（**版式照上游 `ui/main/bookshelf` 收成工具页**：单行页头「书架 · N 本」+ 右侧布局/导入条；顶部**「继续阅读」条** = 最近在读那本的封面 / 第几章 / 共几章 / 上次时间 / 进度条 / 继续按钮，纯前端用 `bookshelf()` 已有字段，不动服务端。**布局 3 档**：封面网格（默认）/ 列表 / 紧凑列表。网格只留一档小封面（`auto-fill minmax(138px,1fr)`，1440 宽实测 7 列、封面 153px；≤640px 固定 3 列 111px）—— 原来的小·中·大三档在 2026-09-29 被用户判掉：「封面网格的大中小，只留下小的，其余不用了」。列表/紧凑沿用上游 `bookshelfLayout` 的 0/1；网格**不照抄**上游的 2~6 列——那是固定屏宽手机上的写法，浏览器窗口从 320 到 3440 都可能，实测同一档在 1440 宽是 567×756 的巨图、在 390 宽是 60×80 的邮票（`tools/verify/shelf-layout-measure.mjs`），列数随窗口自己算；工具栏收成 3 个有名字的档（密度那组按钮已删）。历史值仍读得懂：`grid:sm|md|lg` 与上游数值编号都落到三种视图之一，落 `localStorage` 时只写 `grid|list|compact`；网格卡封面底部有**阅读进度条**（上游 `BookshelfReadProgress` 的位置），作者行让给书名；无封面回落是安静两字书脊，不再重复书名。**书籍分组**（`book_group` + `book_shelf.group_id`，见 §能力波 v20）、批量、导入本地 TXT/EPUB（导入即归到「本地」组并在 toast 里报出是哪几本）、换源、编辑书籍信息、离线缓存、标记已读完、**右键菜单**）· **发现**（读 `exploreUrl` 分栏，实测番茄 460 栏；`{{page}}` 翻页按 bookUrl 去重续页；**点书先弹详情窗**，与搜索页同一个 `BookDetailModal`，点「开始阅读」才进阅读器）· 书源（分组标签筛选、**按可解析性体检**、批量启停/分组/删除、**新建 + 八段结构化编辑 + JSON 原文**、登录、调试 SSE、**行右键**）· 订阅（两张：**书源订阅** = 远程 JSON 地址每 6 小时自动同步；**RSS 订阅** = 手机「订阅」页那些源，导入备份后来读）· 规则（254 条、作用域、预览、导入导出）· 备份（选一个 Legado（安卓端）导出的 zip 直传即恢复：书源 / 替换净化规则 / 书架与进度 / RSS 订阅源 / 分组；没有原生界面的个性化条目原样收进 `data/backup_kept/`，界面上可列出、下载，其中阅读样式与朗读引擎可套到本机设置。WebDAV 那一套已在 2026-09-29 整体删除）· 阅读器（见下）。

**界面内右键**：`ContextMenu.tsx` 一套（`showContextMenu(event, items)` + 挂在 App 根的 `ContextMenuLayer`）。书架卡片右键＝继续阅读/书籍管理/换源/缓存全本/标记已读完/复制书名/移出书架；书源行右键＝编辑/分阶段调试/登录·Cookie/启用·停用/删除。**只在有动作的元素上拦 `preventDefault`**，其余区域浏览器原生菜单照旧。

**内置登录浏览器（Cookie 登录）**：四处修复。① `WebViewProxy` 原来**恒定发桌面 UA**，而书源 `loginUrl` 绝大多数是 `m.` 移动站 —— 桌面 UA 压在移动页上会撑出 980px 版面，登录按钮落到可视区外（就是「点不到登录」）。现在按会话入口主机定 UA（`m|wap|3g|mobile|i.` 前缀或 `.m.` 段 → 安卓 Chrome 移动 UA），整会话锁定，避免中途换身份把 cookie 打乱。② 弹窗**整屏展开**（`.modal-backdrop--webview` 去内边距，弹窗 `100%×100%`、无圆角无投影、iframe 不再 `scale()`）：1440×900 实测弹窗与 iframe 各占满 1440×900，登录按钮不再落在视口外。中途试过「手机 390 / 平板 768 / 铺满」三档缩放切换器，实测对登录毫无帮助（该点不到的还是点不到，还多一层控件），已删。③ **iframe→宿主这条通道原本是死的**：bootstrap 头一行就把 `window.parent` 改写成自己（防站方 framebusting），而自检与地址栏回报用的正是改写后的 `window.parent.postMessage`，还带一句 `parent!==window` 守卫 —— 消息全打进 iframe 自己的收件箱，**自检一次都没送达过，地址栏也从不跟随站内跳转**（表现就是"看不到全部界面"）。现在在任何改写之前先抓 `HOST=window.parent`，统一走 `tell()`。④ 站点**运行时插入**的 `script/img/link/iframe` 不经 HTML 改写、也不走 fetch/XHR 钩子，所以动态注入的 SDK 留在原域＝跨源脚本，报 `Script error.` 且整段不执行。现在给 `HTMLScriptElement.src` 这类属性 setter 与 `Element.setAttribute` 也套上 `toRes()`：番茄首页脚本数 19→20、`_SdkGlueInit is not a function` 消失，只剩风控 SDK `secsdk is not defined` —— 那一步要真实源的 localStorage/cookie，**是沙箱的硬边界，不去绕**。另两处遮挡：`.pwa-install-banner`（z-index 999）与更新浮层（1000）原本压在弹窗（100）之上，整屏登录时正好盖住移动站底部提交按钮，现在 `body:has(.modal-backdrop)` 时让路（合成元素实测 `flex → none → flex`）；`.source-webview-loading` 补 `pointer-events:none`，站点迟迟不触发 `load` 时那层提示不再吃点击。

**登录浏览器取证口径（别再猜）**：`node tools/verify/webview-login-probe.mjs [书名]` 打开真实内置浏览器，宿主侧挂 `message` 监听收页面回报的 `forms/fields/scripts/storage/viewport/targets/errors`；`targets` 逐个给登录控件的矩形、是否在视口内、以及 `elementFromPoint` 反查到的**遮挡者**。两类实测结论：`13小说`（m.13xxs.com）2 表单 / 2 输入 / 3 个登录控件全部 `blocked:false` 可点，整屏渲染正常 —— 内置浏览器对普通站点是好的；`番茄小说`（loginUrl 指向 fanqienovel.com 官网首页）`forms:0 fields:0 targets:[]`，**那页面上根本没有读者登录入口**（是作家专区首页）。所以它"点不到登录"不是我们挡的，而是这本书源的 `loginUrl` 本身没有登录页；脚注现在会把这两种情况分开说。

**能力波 v13 · 登录真的作用到阅读（用户「书源的登录没有处理好」）**：内置浏览器能开、Cookie 也存得下，但登录对阅读**不起作用**，四条各自独立的原因，全部改完复测：
- **引擎按书源主页域名查 Cookie**。`parseSourceHeaders()` 里是 `getSourceCookie(bookSourceUrl, bookSourceUrl)` —— 阅读类站点的书页域名和接口域名经常不是一个（`www.x.com` 有页面、`api.x.com` 出数据），于是内置浏览器登录留下的凭据永远查不到、永远不发。改成**逐跳合成**：`buildRequest()` 用「这一跳真正要访问的 URI」查库（重定向的每一跳都重算），优先级照上游 `AnalyzeUrl.setCookie()`：**库内登录头 → 该域名的 Cookie 罐 → 本次 URL 自带的 `,{options}` 头**，Cookie 按键位合并而不是整串覆盖（否则临时 cookie 会把登录留下的其它键抹掉）。`parseSourceHeaders` 从此只管书源自己的 `header` 字段，`fetch()` 里那份重复的凭据拼装删掉。对照：内置浏览器代理 `WebViewProxy` 早就是按 URI 查的，只有规则引擎这一侧漏 —— 这个不对称就是「看起来登录成功了」的真相。
- **界面里的「粘贴 Cookie」被上一轮安全加固顺手打死**。`login-cookie` 是给「在目标站点上运行的书签/扩展」跨站调用的，判据是 Origin 必须命中书源自己的域名；可我们**自己界面**的 POST 必然带 `Origin: http://127.0.0.1:1234`，永远不命中 → 一点就是 403，页签形同虚设。现在同源这一支单独放行，条件是**必须带有效会话 + CSRF 头**，跨站仍然只认书源域名；`Origin` 与 `Host` 不一致（反代冒名）不算同源。
- **单删书源把凭据留在库里**。`deleteSource()` 只 `delete from source`，`source_login_state`（登录头 + 该站 Cookie 罐）原样留着 —— 用户不再信任这个站点，凭据却还在。批量删除早就连带清了，单删漏了，现在补上同一套（同一事务）。
- **浮层本身不再说谎**：`loginUi` 只有一个「打开登录网页」按钮时不再推荐「填写表单」（改推荐「内置浏览器」），有真字段才推荐表单；状态行从一句「已捕获登录凭据（未自动验证）」改成**具体存了什么**（域名 + 每个域名几条，来自 `/browser/cookies`）；「凭据管理」菜单里删掉与页签重复的「快捷填入 Cookie / 一键同步书签」两项（同一功能两处入口，且共用一个输入框）；Esc 一次关一层（登录头编辑 → 内置浏览器 → 菜单 → 浮层），此前这个浮层是全站唯一不吃 Esc 的；表情符号按钮换成 `Icon` 组件并补 `aria-label`；顺手清掉 6 处从未定义的 `var(--text-muted)`（未定义 `var()` 静默继承，正是那类"看着没问题其实发错令牌"的老坑）。
- 验证：`RuleRunner.effectiveHeaders` 5 条 Kotlin 用例（按请求域名查、登录头与罐按键合并、urlOption 压过库内同名键但不抹别的键、无源时不凭空造头、裸串当 Cookie）+ 删源清凭据 1 条；`tools/verify/source-login-check.mjs` 用两条一次性探针源跑真浏览器 **20/20**（不碰用户真源的凭据，跑完自己删干净）；`tools/verify/authfixes.mjs` 从 6 项扩到 **9 项**（新增同源三条矩阵）。**没做**：`enabledCookieJar` 这个上游字段服务端仍不认（上游用它控制"是否自动保存每跳的 cookie"，我们一直存，行为是上游的超集）。

**能力波 v16 · 备份包里的登录态可以恢复了（承接 §v15 查出的缺口，任务 #39）**：手机 Legado 的 `cookies.json` 整份是 `aes.encryptBase64(GSON.toJson(cookieDao.all))`（`Backup.kt:315-320`），我们原来连条目名都不认，从手机备份恢复过来的人会掉光所有登录态。
- **加密口径逐字照上游 `BackupAES.kt`**：`AES(MD5Utils.md5Encode(password).encodeToByteArray(0, 16))` —— 密钥是**密码 MD5 小写十六进制串的前 16 个字符的 ASCII 字节**（不是 16 字节摘要），模式 ECB / PKCS5 填充，密文 base64。为了不让"自己跟自己 round-trip"掩盖密钥推导错误，测试里钉了一条**用 node `crypto` 独立算出来的密文向量**（`备份密码123` → key `239d482bfd3aa48b`），Kotlin 解密与再加密都必须逐字节吻合。
- **恢复语义**：解密后 `[{url, cookie}]`，`url` 是注册域；老 OkHttp 主键（含 `|`）跳过而不是猜一个键；用 `Database.setSourceCookie` 落库 —— 它按键合并，与上游 `CookieStore.restoreCookie` 同语义，重复恢复不会堆串。**两处与上游有意不同**：① 上游缺密码直接抛错、整个恢复中止，我们只跳过 cookie 这一节并在结果里如实写 `cookiesNote`，不赔上书源和书架；② 凭据**只发给「自己配置里就会访问该域」的书源**（`WebViewProxy.credentialDomains` 复验），不是 `instr(payload, domain)` 一命中就发 —— 否则任何在注释里提一句 `fanqienovel.com` 的源都能领到用户从手机恢复过来的登录 Cookie。

**能力波 v17 · 凭据罐改成按注册域全局共享（任务 #40，2026-09-28 补记）**：v14–v16 把"能不能拿到 Cookie"这条链补齐之后，剩下的问题是**拿到的 Cookie 发不出去**。

**能力波 v22 · WebDAV 现场取证与三处修复（用户「WebDAV 一点不能用，你将他除掉就好了」→ 追问后选「先别删，告诉我怎么不能用」）**

- **① 根本连不上，而且界面在骗人**：`scripts/runtime.mjs:30` 默认 `LEGADO_HOST=127.0.0.1`，手机或另一台电脑发往 `http://<PC-IP>:1234/webdav` 的请求根本没人接；而「文件」页四张指引卡与地址栏用的都是 `location.origin + /webdav`，在手机上就是 `http://127.0.0.1:1234/webdav` —— **指向手机自己**。修法：`WebDavInfoResponse` 新增 `bindAddress / port / lanAddresses`（绑成 `0.0.0.0|::` 时用 `NetworkInterface` 枚举 site-local IPv4，回环与 169.254 一律不报），指引卡与地址卡优先用局域网地址；只绑回环时界面直说「手机必然连不上，要跨设备用把 LEGADO_HOST 设为 0.0.0.0 重启，这同时会关掉本机免登录」。
- **② 填错密码照样能读写**：`requireWebDavAuth` 原来是 `verifyBasicAuthorization(头)` 不通过就继续往下走「本机免登录」支路 —— 于是**错密码被当成"没带凭据"**，实测 `PROPFIND` 错密码 207、`PUT` 错密码 201 并真落文件、无凭据 `GET` 能读到内容。绑回环时风险有限，可一旦有人照指引把 `LEGADO_HOST` 改成 `0.0.0.0`，这就等于整个存储区对局域网匿名敞开，而且界面从不提醒。现在：**只要客户端自称 Basic 并给了密码，密码不对就直接 401 + `WWW-Authenticate`**，不再落到免登录支路（资源管理器/手机 App 也因此才会弹重填，而不是"看着能连其实一直用错的密码"）。
- **③ LOCK 的空桩永不清理**：RFC 4918 与资源管理器「新建文件」要求对**还不存在的文件**加锁并回 201，我们的实现为此真的 `createFile` 一个空桩 —— 但客户端崩溃/取消后这个 0 字节文件就永久堆在存储区（我第一轮取证就留下一个，手工清的）。现在 `DavLock` 记住 `createdStub`，`prune()`（到期）与 `release()`（解锁）时通过注入的回收器删掉，**且只删仍然是 0 字节的**：门禁里 `写过内容的文件绝不回收` 那条就是这条的反向对照。

**能力波 v33 · 夜读模式下的「指定书源」搜索（用户 2026-10-01：「指定源搜索还没做好，你看看在夜读模式下」）**

- **一句话结论：这条报告是真的，而且底下压着两个独立 bug**——一个让下拉在夜读模式下根本看不清，
  另一个让"点了搜索"这件事被页面自己的一次刷新吃掉。两个都修了，各有一条可重跑门禁。
- **① portal 出去的浮层吃不到主题变量**。`Select` 的下拉必须 `createPortal(…, document.body)`
  （书架/订阅/发现各有各的滚动容器与边框，绝对定位会被祖先裁掉），
  而 `--surface` / `--ink` / `--line` 只定义在 `.theme-*` 上，`.theme-*` 只挂在 `.app-shell` 那一层
  → **挂在 body 上的浮层一个变量都解析不到**。实测（把 `<html>` 的主题类摘掉就是修复前的形态）：
  `--surface` 未定义 · 菜单底色 `rgba(0, 0, 0, 0)`（全透明）· 选项文字 `rgb(0, 0, 0)`（纯黑）
  —— 浅色模式下只是描边发虚（所以这个 bug 一直存在却没人报），夜读模式下就是黑字压在深色页上。
  修法：主题**同时挂到 `<html>`**（`main.tsx` 里紧跟标题栏那个 effect），一处生效，
  现在与将来的所有 portal 都自动跟着主题走。
- **② PWA 让页面自己刷新，把正在发起的搜索丢掉**。`registerType: 'autoUpdate'` 生成的 SW 会
  `skipWaiting + clientsClaim`，于是**第一次访问**（页面本来没有 controller）装好 SW 那一刻也会报
  `controllerchange`，而原来的监听无条件 `window.location.reload()`
  → 用户视角是"选了源、点了搜索、页面刷一下、什么都没搜"。
  实测证据：修复前点提交后 `window.__marker` 与拦截器一起消失、`.search-card` 0 条、状态行空；
  修复后同一条路径搜出 50 条。修法两条：只有"本来就被旧 SW 控制着、又被新 SW 接管"才算真更新；
  真更新时若用户正在输入或搜索在飞（界面上有「停止搜索」按钮），推迟 1.5 秒重试而不是当场打断。

## 6. 能力边界（规则语法）

**已支持**（每条都有单测或实测证据）：
`id. class. tag. text. children` 简写与组合符、`@text @textNodes @ownText @html @<attr>`；
JsonPath `$.` `[]` `..` `[?(@.x<10 && @.y=="z")]` 与 **JSON 裸键**（`author` ≡ `$.author`）、`$.data` 数组摊平；
`||` 备选 与 `&&` 并接（**最左分隔符说了算、无优先级**，切分跳过 `{{}}`/`[...]`/引号/`##` 段）；
`##正则##替换`（含出现在 `{{}}` 内部，替换串尾部的空格保留）；
`{{JS 表达式}}`（`java.timeFormat(...)`、`{{(page-1)*20}}`）与 `{{路径||路径}}` 占位；
`@put:{k:规则}` / `@get:{k}`（同一次解析内跨字段共享，`{{k}}` 亦查同一张表）；
`nextTocUrl` 目录分页续取（**1,165 源**在用）与 `nextContentUrl` 正文分页续取（**1,693 源**在用）—— 与上游同形状（`visited` 集合防回环 + 多入口页逐页吃），另加页数硬上限（目录 40 / 正文 30）：服务端是替用户发请求，坏规则不该把开书变成爬站；
`chapterList` 的 `-` 前缀倒序目录（`+` 为显式正序）；
**正文配图**：`<img>`（含懒加载 `data-src`/`data-original`）在净化前换成 `![图片](绝对地址)` 占位行，前端按行还原成 `<img src="/api/book/image?url=&page=">`；代理带 `Referer`（图站防盗链）、按文件头嗅探类型、拒 `image/svg+xml`（代理后与主应用同源，SVG 可带脚本＝自开 XSS 面）、复用封面那套 sha256 落盘缓存、SSRF 逐跳复验。`data:` 内联图丢弃（撑爆缓存）。TTS 跳过图片占位行但保留段落下标，高亮仍对齐 DOM。
`@js:` 行首、**`文字模板@js:代码`**（`result` = 前段求值结果）、`<js></js>` 段后再接取值路径；
`@CSS:`；AnalyzeUrl 的 `,{options}`（**严格 JSON 失败退回宽松规范化**：单引号键值、裸标识符键、全角引号 `“”‘’`、字符串内裸换行/制表、尾随逗号、`//` 与 `/* */` 注释；`body` 写成对象会序列化回 JSON 文本、`headers` 写成字符串会再解析一次、`webView` 如实解析成标志位交给体检。**两种都解析不出来时尾巴照样从 URL 上摘掉**，对齐上游 `analyzeUrl()` 用 `urlNoOption` 的语义 —— 我们原来失败就整串当地址发出去，直接报「URL 格式无效或包含未解析变量」）、`<1,3,5>` 之外的 `{{key}}/{{page}}/{{source.*}}`；
`java.*` 桥：`ajax/get/post/getString/put/getCookie/md5Encode(16)/base64Encode/Decode/hexDecode/encodeURI/timeFormat/parseDate/randomUUID/toJsonString/log/toast/copyText` + `cookie.getCookie/setCookie/removeCookie/mapToCookie/getKey` + `source.*` + `book.getVariable/setVariable` + `chapter.*`；

**明确不支持**（括号内是 4,876 源语料里**实际用到该写法的源数**，别当成"差不多能用"）：
`@Json:`（41 源）、单花括号 `{$.x}` 占位（162 源）、`%%` 排除（17 源，上游实现是按下标交错、语义存疑，未跟）、`@XPath:`（4 源）、`concurrentRate` 按源限速（39 源，当前用全局并发上限）、`<1,3,5>` 按页取址（7 源）。
`webView: true`（484）不执行页面 JS —— 走反向代理尽力抓静态 HTML，抓不到就失败并写日志。
漫画/视频/音乐书源、段评、`purchaseChapter`（VIP 购买）不做。

**与上游的有意差异**：
① 分组标签按 `[,，、\s]+` 切分（上游只按 `,`）—— 因为真实语料里 73 个源用空格分隔（`小说 书源`），不切会导致 91% 的源永远归不进分组；
② `##` 净化结果 trim；
③ 不设身份：没有账号、会话与 CSRF 令牌，写操作只过同源闸门（见 §8）；
④ options 里的未知键当请求头。

## 8. 安全边界
- **服务不设身份**：没有管理员密码、没有登录页、没有会话、没有 CSRF 令牌。用户 2026-09-29 的口径是「咱们这个是开源的，不要那么多条条框框」，而默认绑定就是回环 —— 密码在这台机器上只制造 friction，不制造安全。
- **唯一一道写保护是同源闸门**（`Guard.kt`）：非安全方法的 `Origin` 必须与请求 `Host` 主机+端口一致，否则 403 `cross_origin`；不带 `Origin` 的（curl、命令行、非浏览器客户端）放行。它挡的是"用户访问的任意网页驱动他的浏览器改这个库"，对本机用户零感知。`,authfixes.mjs` 12 条逐形状守着它。
- **改绑 `0.0.0.0` 就是把库交给局域网**：同源闸门不挡同网段的直接读写（它们不带 Origin）。要公网用请自己上反向代理 + 认证，本项目不再内置。
- **SSRF 与沙箱边界不变**：抓取逐跳复验地址、拒绝内网与链路本地、脚本超时受控、iframe 不开 `allow-same-origin`。
- 备份包里的登录态是**用户自己的凭据**，恢复时三条约束：① 密码只在这一次请求的 body 里过，界面不存、日志不打（`WebDavServer` 只记条目数）；② 凭据**只发给自己配置里就会访问该域的书源**（`WebViewProxy.credentialDomains` 复验），不是 payload 里提一句域名就发；③ 密码错/缺只跳过 cookie 这一节并在结果里写明，不牵连书源与书架。**导出侧不做**，所以现在不存在"把凭据写进备份包"这条外泄路径。
- `@js:` 在 Rhino 里执行且 `ClassShutter` 禁全部 Java 反射（`System`/`Runtime` 单测验证过）；**这不等于安全** —— 书源规则本身可能恶意，只导入信任来源。
- 沙箱无 JS 指令数/墙钟上限（`while(true)` 能钉死一个工作线程）—— 已知未修。

## 9. 运行

```bat
node ./start.mjs          启动（读 .env 与内置 LEGADO_* 配置）
node ./stop.mjs           停止
node ./tools\verify\selfcheck.mjs    34 项端到端自检
```

改代码后的构建（**前端产物是打进 jar 的，改完 web 必须重打 jar 才生效**）：

```sh
npm --prefix web run build
node stop.mjs
JAVA_HOME="<本机 JDK 17+ 目录>" \
  "<本机 gradle 8.x>/bin/gradle" --no-daemon \
  -I init-mirror.gradle -Pkotlin.compiler.execution.strategy=in-process :server:fatJar
node start.mjs
```

本机到 Maven Central / plugins.gradle.org 基本不可用，故仓库不改、用 `-I init-mirror.gradle` 换阿里云计算巢镜像，JDK 用 17（上游 toolchain 21 拉不到，本地补丁见 `local-patches.diff`）。
